# Week 3 — 그래픽스 파이프라인과 셰이더

## 1. 실습 목표

이번 3주차 실습에서는 WebGL2의 그래픽스 파이프라인을 직접 구성하면서
정점 데이터가 화면의 픽셀로 출력되는 과정을 확인하였다.

먼저 구체를 이용하여 자전과 공전의 차이를 확인하고,
버텍스 셰이더와 프래그먼트 셰이더의 역할을 학습하였다.

이후 기본 구체를 수정하여 얼음 행성을 제작하였다.
단순히 행성의 색만 변경하는 것이 아니라 프래그먼트 셰이더 내부에서
얼음 표면, 적도 구름, 번개, 극지방의 오로라를 계산하고,
행성 주변에는 별도의 메시로 불타는 고리를 제작하였다.

# 2. Task 1 — 자전과 공전

## 2-1. 자전

첫 번째 실습에서는 구체가 자신의 중심을 기준으로 회전하도록 하였다.

```javascript
const ballModel =
  M4.multiply(
    M4.translate(0, 1.0, 0),
    M4.rotateY(time)
  );
```

`M4.rotateY(time)`을 사용하면 시간이 증가함에 따라
구체가 Y축을 기준으로 계속 회전한다.

이 경우 구체의 위치 자체는 변하지 않고
자신의 중심을 기준으로 방향만 바뀌기 때문에 **자전**이 된다.

## 2-2. 공전

다음으로 회전과 이동의 순서를 변경하여 공전을 구현하였다.

```javascript
const ballModel =
  M4.multiply(
    M4.rotateY(time),
    M4.translate(2.2, 1.0, 0)
  );
```

구체를 먼저 원점에서 떨어진 위치로 이동시킨 뒤
전체 위치를 Y축 기준으로 회전시키면
구체가 원점을 중심으로 원형 궤도를 따라 이동하게 된다.

따라서 행렬의 종류가 같더라도
곱셈 순서에 따라 자전과 공전이라는 서로 다른 움직임이 만들어진다는 것을 확인하였다.

# 3. Task 1 — 프래그먼트 셰이더 확인

프래그먼트 셰이더에서는 각 픽셀의 최종 색상을 결정한다.

실습에서는 법선 벡터의 성분을 RGB 값으로 변환하여
구체의 방향에 따라 서로 다른 색상이 나타나도록 하였다.

```glsl
vec3 N = normalize(vNormal);
vec3 normalColor = N * 0.5 + 0.5;
fragColor = vec4(normalColor, 1.0);
```

법선 벡터의 각 성분은 원래 `-1.0 ~ 1.0` 범위를 가지므로
이를 RGB 색상으로 사용하기 위해

```text
N * 0.5 + 0.5
```

계산을 사용하여 `0.0 ~ 1.0` 범위로 변환하였다.

이를 통해 프래그먼트 셰이더가 정점 자체가 아니라
화면에 그려지는 각각의 픽셀 색상을 계산한다는 것을 확인할 수 있었다.

# 4. Task 2 — 얼음 행성 제작

## 4-1. 제작 의도

이번 Task 2에서는 **차가운 얼음 행성과 매우 뜨거운 고리가 공존하는 행성**을 만들고자 하였다.

행성의 대부분은 얼음으로 덮여 있지만,
행성 주변에는 가스와 휘발성 물질로 이루어진 뜨거운 고리가 존재한다는 설정이다.

고리는 붉은색과 황금색으로 빛나며 계속 불타고 있고,
고리와 가장 가까운 적도 부근은 열의 영향을 받아
얼음이 녹고 많은 수증기가 발생하여 두꺼운 구름층이 형성된다.

반대로 적도에서 멀어질수록 다시 차가운 푸른 얼음 지형이 나타나며,
북극과 남극에는 행성과 고리의 극단적인 환경 차이로 인해
청록색과 보라색의 오로라가 발생하도록 표현하였다.

또한 적도의 불안정한 구름층에는 번개가 발생하도록 하여
단순한 얼음 행성이 아니라 여러 기상 현상이 동시에 발생하는
불안정하고 역동적인 행성을 표현하고자 하였다.


## 4-2. 보는 사람이 느끼길 바란 점

이 행성을 처음 보았을 때 차가운 얼음과 뜨거운 불이라는
서로 반대되는 환경이 한 행성에 동시에 존재한다는 점이
가장 먼저 눈에 들어오도록 만들고 싶었다.

또한 고리가 단순한 장식물이 아니라
행성의 적도 구름과 번개 등의 기후 현상에 영향을 주고 있다는 설정을 통해,
각각의 시각 요소가 서로 연결되어 있는 하나의 행성처럼 보이도록 하는 것을 목표로 하였다.


## 4-3. 실습 예시와 다르게 표현한 점

기본 실습에서는 구체의 색과 조명, 회전 등을 확인하는 것이 중심이었다.

이번 결과물에서는 기본 구체를 그대로 사용하는 대신
프래그먼트 셰이더에서 위치와 법선 정보를 이용하여
얼음 표면, 적도 구름, 번개, 오로라를 직접 계산하였다.

또한 구체 외부에 `makeRing()`으로 별도의 고리 메시를 제작하고
행성과 같은 위치 및 기울기를 적용하여
하나의 행성 시스템처럼 보이도록 확장하였다.

# 5. 구현 방법

## 5-1. 얼음 표면

얼음 표면이 완전히 단색으로 보이지 않도록
법선 벡터의 X, Z 성분에 서로 다른 주파수의 `sin()` 함수를 적용하였다.

```glsl
float iceNoise =
      sin(N.x * 8.0 + N.z * 5.0) * 0.10
    + sin(N.z * 13.0 - N.x * 7.0) * 0.06
    + sin((N.x + N.z) * 18.0) * 0.03;
```

하나의 `sin()` 함수만 사용하면 일정한 줄무늬가 반복되기 때문에,
방향과 주파수가 다른 세 개의 파동을 더하였다.

그 결과 구체 표면에 일정하지 않은 밝기 변화가 만들어지고,
행성이 회전할 때 얼음 표면의 변화도 함께 움직여 자전이 더 잘 보이도록 하였다.

얼음 색은 짙은 남색, 푸른색, 흰색을 `mix()`로 혼합하였다.

```glsl
vec3 deepIce  = vec3(0.015, 0.10, 0.24);
vec3 blueIce  = vec3(0.06, 0.30, 0.58);
vec3 whiteIce = vec3(0.78, 0.92, 1.00);

float iceVariation = clamp(0.48 + iceNoise, 0.0, 1.0);

vec3 iceColor = mix(deepIce, blueIce, 0.55);
iceColor = mix(iceColor, whiteIce, iceVariation * 0.55);
```


---

## 5-2. 적도 폭풍 구름

고리의 열 때문에 적도 부근의 얼음이 녹아
수증기가 모이고 두꺼운 구름층이 생겼다는 설정으로 제작하였다.

먼저 법선 벡터의 Y값을 사용하여 위도를 계산하였다.

```glsl
float latitude = abs(N.y);
float equatorDist = latitude;
```

적도에서는 `N.y`가 0에 가까우므로 `latitude`도 0에 가까워지고,
극지방으로 갈수록 값이 1에 가까워진다.

구름의 경계가 완벽한 직선 띠가 되지 않도록
서로 다른 방향과 크기의 파동을 합성하였다.

```glsl
float cloudShape =
      sin(N.x * 3.7 + N.z * 2.3 + uTime * 0.04) * 0.45
    + sin(N.x * 5.1 - N.z * 3.8 - uTime * 0.025) * 0.30
    + sin((N.x - N.z) * 7.3) * 0.15;

float cloudWidth =
    0.27 + cloudShape * 0.055;
```

그리고 `smoothstep()`을 사용하여
구름과 얼음 사이의 경계가 갑자기 끊어지지 않고
부드럽게 이어지도록 하였다.

```glsl
float cloudBand =
    1.0 - smoothstep(
        cloudWidth,
        cloudWidth + 0.13,
        equatorDist
    );
```

최종적으로 `mix()`를 이용해 얼음 표면과 구름 색상을 합성하였다.

```glsl
vec3 color =
    mix(
        iceColor,
        cloudColor,
        cloudBand * 0.88
    );
```

이 계산을 통해 적도 주변에는 넓은 흰색 구름층이 형성되고,
극지방으로 갈수록 다시 푸른 얼음 표면이 나타나도록 하였다.


---

## 5-3. 적도 구름의 번개

번개는 행성 전체가 아니라
적도의 구름층 안에서만 발생하도록 제한하였다.

```glsl
float lightningZone =
    equator *
    smoothstep(0.35, 0.70, melt);
```

번개가 곧은 선처럼 보이지 않도록
Y축 위치에 따라 서로 다른 주파수의 `sin()` 파동을 합성하였다.

```glsl
float lightningPath =
      sin(N.y * 38.0 + uTime * 0.4) * 0.055
    + sin(N.y * 71.0 - uTime * 0.2) * 0.025
    + sin(N.y * 113.0) * 0.012;
```

또한 시간값 `uTime`을 이용하여
번개가 계속 켜져 있는 것이 아니라 짧은 순간에만 나타나도록 하였다.

```glsl
float flashWave =
    sin(uTime * 17.0) *
    sin(uTime * 11.3 + 1.7);

float lightningFlash =
    smoothstep(
        0.72,
        0.96,
        flashWave
    );
```

번개의 중심은 밝은 청백색,
주변은 푸른 발광으로 나누어 표현하여
번개가 주변 구름을 순간적으로 밝히는 것처럼 만들었다.


---

## 5-4. 극지방 오로라

오로라는 적도가 아니라 고위도에서만 나타나도록
`latitude`와 `smoothstep()`을 이용하였다.

```glsl
float auroraBand =
    smoothstep(0.55, 0.82, latitude);
```

오로라 역시 일정한 줄무늬가 되지 않도록
큰 파장의 두 개의 `sin()` 함수를 합성하였다.

```glsl
float flowA =
    sin(N.x * 2.2 + N.z * 2.8 + uTime * 0.35);

float flowB =
    sin(N.x * 1.3 - N.z * 2.0 - uTime * 0.22);

float flow =
    0.5 +
    0.18 * flowA +
    0.12 * flowB;
```

이후 `smoothstep()`으로 경계를 흐리게 만들어
선보다는 넓은 빛의 막처럼 보이도록 하였다.

```glsl
flow = smoothstep(0.20, 0.78, flow);
```

색상은 청록색과 보라색을 시간에 따라 섞었다.

```glsl
vec3 auroraCyan   = vec3(0.00, 1.00, 0.78);
vec3 auroraPurple = vec3(0.48, 0.18, 1.00);

vec3 auroraColor =
    mix(
        auroraCyan,
        auroraPurple,
        colorShift
    );
```

마지막에는 기존 표면색을 완전히 덮는 방식이 아니라
계산된 색상에 오로라 값을 더하여
스스로 빛나는 반투명 발광처럼 보이도록 하였다.

## 5-5. 얼음 지역의 흩어진 구름

처음에는 적도에만 구름이 존재했기 때문에
행성 표면이 지나치게 단순하게 보였다.

그래서 지구의 구름처럼 적도 이외의 얼음 지역에도
일부 구름이 흩어져 보이도록 추가하였다.

```glsl
float cloudField =
      sin(N.x * 3.2 + N.z * 5.0 + uTime * 0.025) * 0.50
    + sin(N.x * 5.7 - N.z * 2.4 - uTime * 0.018) * 0.30
    + sin(N.x * 2.1 + N.y * 4.0 + N.z * 3.1) * 0.20;
```

서로 다른 방향의 큰 파장을 합성하여
완전히 규칙적인 무늬가 되지 않도록 하였다.

```glsl
float scatteredCloud =
    smoothstep(0.15, 0.62, cloudField);
```

적도 구름과 겹치지 않도록 `awayFromEquator`를 곱하고,
극점에서는 `polarFade`를 이용해 다시 서서히 사라지도록 하였다.

```glsl
float awayFromEquator =
    smoothstep(0.24, 0.42, latitude);

scatteredCloud *= awayFromEquator;

float polarFade =
    1.0 - smoothstep(0.82, 0.98, latitude);

scatteredCloud *= polarFade;
```

최종 강도를 낮게 설정하여
얼음 표면을 완전히 가리지 않는 얇은 구름처럼 표현하였다.

## 5-6. 불타는 행성 고리

행성 주변의 고리는 구체와 별도로
`makeRing()` 함수를 만들어 직접 생성하였다.

고리의 각 정점 위치는 원의 매개변수식을 이용하였다.

```javascript
const a = (i / segments) * Math.PI * 2.0;
const c = Math.cos(a);
const s = Math.sin(a);
```

안쪽 정점은

```javascript
positions.push(
  innerRadius * c,
  0.0,
  innerRadius * s
);
```

바깥쪽 정점은

```javascript
positions.push(
  outerRadius * c,
  0.0,
  outerRadius * s
);
```

으로 계산하였다.

따라서 같은 각도 `a`에서 반지름이 서로 다른 두 정점을 만들고,
이 정점들을 삼각형으로 연결하여 원형 고리 메시를 만들었다.

안쪽에는 붉은 주황색,
바깥쪽에는 황금색을 지정하였다.

```javascript
colors.push(1.0, 0.12, 0.01);
colors.push(1.0, 0.68, 0.05);
```

프래그먼트 셰이더에서는 시간값을 이용해
두 개의 파동을 계산하였다.

```glsl
float flow1 =
    sin(uTime * 3.0 + vColor.g * 7.0) * 0.5 + 0.5;

float flow2 =
    sin(uTime * 4.7 - vColor.g * 5.0) * 0.5 + 0.5;

float fire =
    flow1 * 0.65 +
    flow2 * 0.35;
```

두 파동의 속도를 다르게 설정하여
고리의 밝기가 완전히 일정하게 변하지 않도록 하였다.

```glsl
vec3 ringColor =
    mix(
        orangeFire,
        goldFire,
        0.25 + fire * 0.45
    );
```

이를 통해 붉은색과 황금색이 미세하게 변화하면서
뜨거운 가스가 흐르는 고리처럼 보이도록 표현하였다.

# 6. 행성의 움직임과 배치

행성은 기본 구체보다 크게 보이도록 확대하였다.

```javascript
const planetScale = M4.scale(1.8, 1.8, 1.8);
```

시간에 따라 Y축으로 회전시켜 자전을 구현하였다.

```javascript
const planetSpin = M4.rotateY(time * 0.22);
```

또한 실제 행성과 비슷하게 자전축을 23.5도 기울였다.

```javascript
const planetTilt =
    M4.rotateX(23.5 * Math.PI / 180);
```

행렬은

```text
크기 → 자전 → 자전축 기울기 → 위치
```

순서로 적용하였다.

```javascript
let model = M4.multiply(planetSpin, planetScale);
model = M4.multiply(planetTilt, model);
model = M4.multiply(planetPosition, model);
```

고리 역시 행성과 같은 위치와 23.5도의 기울기를 사용하여
행성 중심을 감싸도록 배치하였다.

# 7. 제작 과정에서 발생한 문제와 수정

## 7-1. 구름이 점처럼 보였던 문제

처음 얼음 지역에 구름을 추가했을 때
구름이 넓은 덩어리처럼 보이지 않고
표면에 작은 흰색 점들이 찍힌 것처럼 나타났다.

구름 패턴의 주파수가 너무 높거나
임계값이 너무 강하면 패턴이 작은 영역으로 잘려
점처럼 보일 수 있다는 것을 확인하였다.

그래서 사용하는 `sin()`의 주파수를 낮추고
`smoothstep()`의 범위를 넓혀
구름의 경계가 넓고 부드럽게 이어지도록 수정하였다.


## 7-2. 구름이 규칙적인 줄무늬처럼 보였던 문제

단순한 하나의 `sin()` 함수로 구름을 만들었을 때는
행성 표면에 일정한 간격의 줄무늬가 나타났다.

실제 구름처럼 불규칙한 형태를 만들기 위해
X, Y, Z 방향이 서로 다른 여러 `sin()` 파동을 합성하였다.

그 결과 하나의 규칙적인 파동이 반복되는 현상을 줄이고
조금 더 자연스럽고 불규칙한 구름 형태를 만들 수 있었다.


## 7-3. 셰이더 변수 중복 선언 오류

구름 코드를 수정하는 과정에서 기존 코드가 남아 있는 상태에서
새로운 구름 코드를 다시 추가하여 프래그먼트 셰이더 컴파일 오류가 발생하였다.

오류 메시지는 다음과 같았다.

```text
'scatteredCloud' : redefinition
'awayFromEquator' : redefinition
'polarFade' : redefinition
'scatteredCloudColor' : redefinition
```

이는 같은 이름의 변수를 같은 `main()` 함수 안에서
두 번 선언했기 때문에 발생한 문제였다.

중복된 기존 구름 코드를 제거하고
각 변수가 한 번만 선언되도록 수정하여 해결하였다.

이 과정을 통해 GLSL에서도 같은 스코프 안에서는
같은 이름의 변수를 중복 선언할 수 없다는 것을 확인하였다.


## 7-4. 고리가 행성과 어울리지 않았던 문제

처음 고리를 추가했을 때는 단순한 주황색 원처럼 보여
행성과 별개의 물체처럼 느껴졌다.

이를 수정하기 위해 안쪽과 바깥쪽의 색을 다르게 설정하고,
프래그먼트 셰이더에서 시간에 따라 붉은 주황색과 황금색이
미세하게 변화하도록 만들었다.

또한 행성과 동일한 23.5도 기울기와 위치를 적용하여
고리가 행성의 적도 주변을 자연스럽게 감싸도록 수정하였다.

# 10. 느낀 점

이번 실습을 통해 3D 모델의 형태 자체를 복잡하게 만들지 않아도
프래그먼트 셰이더의 계산만으로 표면에 다양한 시각적 특징을
만들 수 있다는 점을 확인하였다.

특히 `sin()` 함수의 주파수와 방향을 어떻게 조합하는지에 따라
규칙적인 줄무늬, 불규칙한 구름, 번개, 오로라처럼
전혀 다른 형태를 표현할 수 있다는 점이 인상적이었다.

또한 결과가 원하는 모습과 다르게 나왔을 때
단순히 값을 무작정 바꾸는 것보다
어떤 계산 때문에 점이나 줄무늬가 만들어지는지를 확인하고
주파수와 `smoothstep()` 범위를 조정하는 과정이 중요하다는 것을 알게 되었다.
